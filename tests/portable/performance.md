# CPU cost of the portable Oxford signal chain

Four Oxford Inflator instances took 102.6 µs per 64-sample vector with the shared Gen meter and 99.1 µs with the v1.4 native gains and meter. The measured difference was 0.9 µs per instance, or 3.5% of the full v1.4 chain's processing time. With two stock stereo `loudness~` objects per instance, the full chain took 15% longer than the single Gen implementation. Both also supplied RMS and sample peak readings.

| Four Oxford voices in standalone Max | Typical µs per vector | 95th percentile µs per vector | Range of typical values across the four runs |
| --- | ---: | ---: | ---: |
| Oxford VST3 in `vst~` alone | 94.6 | 158.8 | 90.8–97.4 |
| Oxford with the v1.4 native gains and meter | 99.1 | 160.6 | 98.1–100.4 |
| Oxford with embedded gains and a single Gen meter | 102.6 | 168.3 | 100.8–104.0 |
| Oxford with embedded gains, Gen RMS/peak and two `loudness~` objects | 118.4 | 212.9 | 117.1–119.4 |

A 64-sample vector at 44.1 kHz allows 1,451 µs of processing time. For four voices, the 3.5 µs difference between the portable chain and v1.4 occupied about 0.24 percentage points of that budget. The figures measure elapsed time on the audio thread. Live's track scheduling, display updates and other work outside that thread need a separate measurement. The direct VST3 row uses Max as the host. Other computers, audio settings and presets can give different results.

## Repeating the comparison

1. Use a licensed Oxford Inflator VST3, a saved copy of the published v1.4 device, and a local portable build. Set Max to 44,100 Hz and a 64-sample signal vector. This run used the Max 9.1.5 bundled with Live 12 Suite on an Apple M3 Max. Mute the hardware output of the test patch.
2. Build four branches in Max. In each, use `poly~` with four voices, signal I/O, and parallel processing off. The direct voice contains only `vst~`. For the v1.4 voice use the two `m4lwrappergainstage~` objects from the local release, in their original pre and post positions. Use the portable device's two embedded gain subpatches and its meter for the Gen voice. For the hybrid voice, omit the four K-weighting filters and their energy accumulators from the Gen meter, then measure input and output with one `loudness~ 2 @interval 100` each. Connect the short-term outlets in the hybrid. Keep the RMS and sample-peak calculation active on all metered paths.
3. Feed each branch an identical 301 Hz square wave with amplitudes 0.05 on the left and 0.03 on the right. Load `Oxford Inflator` via `plug_vst3`. Leave the plug-in in its initial state apart from setting VST parameter index 2 (Max's one-based indexing) to a normalized 0.58. Set Pre Gain and Post Gain to 0 dB, enable the wet path and send a running meter epoch (`metering 3`). Verify that every VST reports eight parameters for this plug-in version and that the metered branches produce valid, settled readings. All branches must process audible, nonzero input even though the hardware output is muted.
4. For microsecond measurements, use an audio-thread timing probe. A source records a monotonic timestamp immediately after generating its stereo vector. A sink records a second timestamp on entry, stores the difference in a preallocated array, then writes silence. Connect each sink's signals to the next source's inlets to force serial ordering even though each source generates its own signal. Each start/stop pair then surrounds just one four-voice branch inside the same DSP callback. The original probe used `mach_absolute_time` on macOS. An equivalent monotonic high-resolution clock can be used on Windows. Sort and summarize the stored samples outside the audio callback. Test instruments are separate from distributed devices.
5. Use the orders A–B–C–D, D–C–B–A, C–A–D–B and B–D–A–C, where A through D are the table rows. Allow at least one full three-second meter window after setup. For each order, collect three complete 1.5-second timing windows with at least 1,000 vectors apiece. Check that the vector size and rate stayed constant, each branch received the same number of vectors to within a few callbacks, and their post-VST audio levels agree. Each case in this test included approximately 12,400 timed vectors.
6. Within each window compute median and 95th-percentile time. Within each run take the median of the three window medians and the median of the three 95th percentiles. The table gives the arithmetic mean across the four run statistics and the range across the four run medians. Execution order affected results enough to make a single timing run misleading. Positions are equally represented in the overall comparison.

All four runs used the same embedded pre-gain and post-gain patchers, including the meter reset on DSP restart. The v1.4 and Gen meters on the Oxford test signal agreed to within 0.000000001 dB for all six values. The hybrid's two stock loudness readings agreed to the same precision on that signal.
